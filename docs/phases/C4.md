# C4 — P3 Gaz et Ancrage, puis P4 Signal (session A)

Spec : `docs/spec/26_MECANIQUES_THEORIQUES.md` §4 (P3) et §5 (P4). Audit : `docs/reports/C0-audit.md` (lignes P3, P4). Valeurs d'équilibre `[A]` dans `data/balance/`.

## Tâches
**Étape 1 — P3** (`src/sim/gas/`, `data/balance/gas.json`, schéma `GasBalanceSchema`)
1. Registre de pertes d'ancrage séparé de la carte ; destruction (Titan, incendie, démolition, artillerie) ; ancrage impossible sans support ; chemins d'ancrage en ancrage.
2. Carte d'ancrage réelle et estimée (renseignement P6 → fourchette).
3. Fenêtre de coupe (vitesse, angle, compétence, usure, stress) et cône d'ouverture.
4. Coût stratégique : coût attendu, ponction du stock gaz/acier, règlement de fin de bataille (conservation), réserve de dépôt, lances de foudre (≥ 850).
5. Branchement ultérieur (hors étape 1) : `battle.ts` (utiliser le registre), conseil (coût visible), dépôts-objectifs.

**Étape 2 — P4 Signal** : signaux (visibilité monotone selon météo), relais et fantômes d'information, brouillard à 3 niveaux, doctrine programmable (table de règles).

## Critères d'acceptation
- `npx vitest run tests/sim/gas` vert (déterminisme, monotonie de la ponction, ancrage impossible sans support, suppression d'ancrage change les chemins, conservation du gaz).
- `npm run data:validate` code 0 (gaz.json validé par Zod) ; `npm run typecheck && npm run lint` code 0.
- `npm run sim:selftest` et empreintes de référence inchangées (P3 non branché au tick).
- P4 : tests (a) à (d) de la spec 26 §5 ; `npm run sim:tactical`.
- `npm run verify` code 0.
