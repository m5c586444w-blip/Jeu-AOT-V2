# C3 — Prérequis neutres du multijoueur (session A)

## Tâches
1. **Siège** : type `SeatId` (`src/sim/core`) ; champ `owner: SeatId` sur piles/armées, escouades/formations de bataille, provinces, institutions. Valeur par défaut = siège du joueur solo (migration des sauvegardes et des mondes générés ; empreintes de référence : changement délibéré à justifier dans `DECISIONS.md`).
2. **Commandes typées sérialisables** : toute action du joueur passe par un type union `Command` (Zod, JSON pur) portant `seat`, `tick`/`day` ; un journal de commandes ; applicateur pur `applyCommand(state, cmd)` ; l'UI ne mute plus l'état directement pour les actions couvertes (au moins : ordres d'armée, ordres de bataille, décisions du conseil existantes).
3. **Rejeu** : même journal + même graine → même empreinte (3 exécutions).
4. **Connaissance par faction** : structure `knowledge[factionId]` pour la visibilité ; brouillard par siège (interface, pas d'hypothèse « un seul joueur »).
5. Rien dans `src/net` (C13).

## Critères d'acceptation
- `npm run verify` code 0, tests existants verts (empreintes changées seulement avec D-nnn).
- `tests/sim/replay-commands.test.ts` : 3 exécutions → même empreinte ; JSON.parse(JSON.stringify(cmd)) idempotent.
- `grep -rn "Math.random\|Date.now" src/sim` vide.
- Test de signature : un second siège ne peut pas commander les entités du premier (commande rejetée).
