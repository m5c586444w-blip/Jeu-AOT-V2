# C1 — Cadre d'interface unique (ERRATA_V3 §3)

Plan : `docs/coord/PLAN_FONCTIONNALITES.md` (C1). Constat : `docs/reports/C0-audit.md` §3 (la bataille recouvre barre supérieure et menu de gestion : `.bataille { position: fixed; inset: 0; z-index: 27 }`).

## Principe
Un seul cadre (barre supérieure `.bandeau` avec alertes `.bandeau__alerte`, menu de gestion `.gestion`, fil de notifications `.notifications`), monté une fois par `gameScreen.ts`, présent dans tous les modes. Aucun mode ne le recouvre : la bataille et les fenêtres occupent l'espace **entre** les deux barres (variables `--bandeau-h` et `--gestion-h`, mesurées par le `Hud`). Réduction : seulement par le bouton explicite `[data-action="cadre"]` de la barre supérieure, qui reste visible dans tous les modes (réduit : ressources, alertes et menu de gestion masqués ; tête, date, vitesse et bouton restent).

## Tâches
1. `.bataille` (2D et temps réel) bornée par `top: var(--bandeau-h)` / `bottom: var(--gestion-h)`, sous les registres (le menu de gestion reste utilisable pendant la bataille).
2. Fil de notifications : parent `.ecran`, `position: fixed` sous la barre supérieure, au-dessus de la bataille et des registres ; à gauche de la scène pendant une bataille.
3. Fenêtres modales (options, bordereau, dossier d'événement) : ancrées entre les deux barres.
4. `Hud.setReduced` + bouton, clé i18n `hud.cadre_reduire` / `hud.cadre_afficher`.
5. `npm run smoke:cadre` (`src/tools/smoke-cadre.ts`) : modes carte, conseil, options, bataille (temps réel), bataille + registre, cadre réduit puis réaffiché, retour carte, tutoriel ; 1366 × 768 et 3840 × 2160 ; mesure de présence, visibilité et recouvrement (`elementFromPoint`) ; captures `docs/screenshots/c1-*`.

## Critères d'acceptation
- `npm run smoke:cadre` code 0 (sortie collée dans `docs/reports/C1.md`).
- `npm run verify` code 0.
- Captures relues une à une (3 lignes de description, ≥ 3 défauts possibles) dans le rapport ; relecture par un sous-agent distinct.
