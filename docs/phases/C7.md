# C7 — Pilier P5 « L'Horloge » (spec 26 §6)

**Objectif.** Module pur `src/sim/clock/` : suspicion et démasquage, contrôle et autonomie des porteurs, extraction, arbitrage de roster, invariant des Neuf, lien avec l'horloge des 13 ans existante (`src/sim/shifters/shifters.ts`). Paramètres `[A]` dans `data/balance/clock.json` (schéma `ClockBalanceSchema`, `src/data/balance.ts`). Modèle de structure : P1 (`wall`), P3 (`gas`), P4 (`signal`).

## Tâches
1. `suspicion.ts` : suspicion **par faction observatrice** (témoin, anomalie, fuite, interrogatoire, transformation vue), couverture (infiltrés), érosion, décroissance, seuil de démasquage (événement), faux soupçon sur un innocent.
2. `view.ts` : vue par faction et par siège ; un porteur non démasqué n'apparaît jamais (test de fuite).
3. `control.ts` : contrôle (volonté, stress, liens, ordre contraire), autonomie, désobéissance, choix d'action par modèle de Titan, délai de réaction, porte de transformation (mains entravées, surprise).
4. `extraction.ts` : objectif de capture (identité connue exigée, arme de contention, tués vs capturés) et pont vers `ShiftersState.captured` (héritage préparé possible).
5. `roster.ts` : Neuf (invariant), horloge utile (usure), coût de projection, conseil utiliser/garder, synchronisation avec les héritages.
6. Tests `tests/sim/clock/*.test.ts` (dont un test sur le monde réel : 13 ans de `dailyShifters`).

## Critères d'acceptation
- `npm run typecheck && npm run lint` verts ; `npm run data:validate` liste `clock`.
- `npx vitest run tests/sim/clock` : seuils, monotonie, déterminisme, fuite, invariant des Neuf, chaque paramètre de `clock.json` exercé.
- `npm run verify` vert ; aucune empreinte modifiée (module non branché au tick).

## Hors périmètre
Branchement au tick et aux commandes, écran Porteurs, exécution des ordres généraux en bataille (`tactical/shifters.ts`), perte de contrôle en combat (déjà dans `tactical`, `shifters.json:control`), événements scénarisés, propagation réseau.
