## 1. Règles propres à la phase

- Tout le code de l'essai est dans `src/render/tactical3d`. Hors de ce dossier, seuls deux points d'entrée changent :
  - le routage de `src/main.ts` (`/proto3d` ou `?proto3d`), par un import dynamique ;
  - le lien de la console debug (F2).
- three.js n'est importé que dans `src/render/tactical3d`. Une règle ESLint l'interdit ailleurs, et un test le prouve.
- three.js est chargé à la demande (`import()`), et seulement si WebGL est disponible : il n'entre pas dans le bundle principal.
- Aucun asset externe : géométries, matériaux et textures sont procéduraux (canvas dessiné par code).
- Aucune copie de design de l'œuvre ; pas de sang ni de gore.
- Les variations visuelles viennent d'une graine locale (générateur pseudo-aléatoire seedé). `Math.random` est interdit dans le dossier par règle ESLint.
- Chaque capture est revue selon CLAUDE.md ligne 14 : description en 3 lignes, au moins 3 défauts possibles.
