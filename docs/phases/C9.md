# C9 — Intégration : armées en piles, bataille jouable de bout en bout

Plan : `docs/coord/PLAN_FONCTIONNALITES.md` (C9). Dépend de C1, C4, C5. Cette fiche couvre l'étape 1 (branchement des piliers au tick) ; la partie bataille/carte (piles visibles, `smoke:bataille`) suivra.

## Principe
Les sept piliers (`gas`, `signal`, `wall`, `clock`, `tide`, `truth`, `registry`) sont des modules purs non branchés (D-160 à D-162 et suivants). Chacun est branché **seul**, par un commit, derrière un drapeau d'état : `GameState.pillars?.<pilier>` absent = pilier inactif, aucune empreinte ne change. Une commande typée sérialisable (`Enable<Pilier>`, classée dans `FACTION_COMMANDS`) crée l'état ; le tick n'appelle le pilier que s'il existe. Données dans `data/balance/` avec schéma Zod (`src/data/balance.ts`). Activation par défaut d'un pilier : décision séparée (D-nnn), en dernier.

## Ordre de branchement (un commit par pilier)
1. **wall** (P1) — fait (étape 1) : `EnableWall`, `data/balance/wall_layout.json`, `src/sim/wall/tick.ts`. Reste : écriture en retour sur les provinces et la famine d'`economy.ts`, alertes, écran « Mur ».
2. **registry** (P7) — peu de couplage (morts nommés) ; branché sur `CharacterDies` et les pertes de bataille.
3. **clock** (P5) — après `shifters` (porteurs, 13 ans) ; lecture seule d'abord.
4. **truth** (P6) — dossiers sur `intel` et `events` ; lecture seule d'abord.
5. **gas** (P3) — ravitaillement et ancrage : couplage `armies` et `tactical`, empreintes tactiques à rebaser.
6. **signal** (P4) — après gas ; brouillard de commandement en bataille.
7. **tide** (P2) — **reporté (D-173)** : grille mondiale inadaptée (≈ 316 000 cellules) ; intégration par grille régionale à la demande dans `armies`, fiche de conception à rédiger. Prévu initialement : rencontres (`armies/layer`, `routes.ts`, `battle.ts`) ; c'est lui qui relie carte, rencontre et bataille.

## Critères d'acceptation (chaque pilier)
- `npm run verify` code 0 (sortie collée dans le rapport).
- Test de rejeu vert (même journal, même empreinte) et test d'intégration du pilier : scénario 850, 365 jours, conservation des quantités, déterminisme sur 2 exécutions, aller-retour de sauvegarde.
- `npm run sim:selftest` : empreintes de référence **identiques** tant que le pilier est désactivé ; toute modification d'empreinte est délibérée, avec sa décision `D-nnn` dans `docs/DECISIONS.md`.
- `src/sim` pur (ni DOM, ni `Math.random`, ni `Date.now`, ni `any`).

## Hors périmètre de l'étape 1
Piles sur la carte, `smoke:bataille`, `smoke:cadre`, écrans des piliers, activation par défaut.
