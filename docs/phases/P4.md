## 0. Périmètre

**Livrables (05 §5)** : scène tactique, ODM (ancrage, rail, gaz), Titans purs + IA, escouades, signaux, lames et usure, journal de combat, 4 cartes.
**Acceptation (05 §5)** : 300 unités à 60 FPS ; déterminisme ; mort individuelle expliquée ; auto-résolution cohérente avec le combat joué (±15 % sur les pertes moyennes).

**Architecture**
- **Simulation** : `src/sim/tactical`, pas fixe de 20 Hz (03 §1), entièrement déterministe (Rng injecté, aucune horloge). Positions en mètres (x, y au sol, z en hauteur ; 2.5D, 03 §1.3). Index spatial en grille pour les ancrages et les voisins (03 §14).
- **Rendu** : `src/render/tactical`, vue oblique façon gravure (04 §4), interpolé entre deux pas. Pause active ; ralenti ×0,25 et ×0,5 ; vitesses ×1 et ×2.
- **Ordres** : une bataille = graine + scénario + journal d'ordres horodatés (en pas). Le rejeu est donc exact (F-CMB-30).
- **Lien avec les expéditions** (F-EXP-18, ouvert en P4) :
  - une expédition peut demander à **jouer** ses engagements ;
  - un engagement met alors la campagne en pause, avec une bataille en attente ;
  - la bataille jouée se termine par la commande `ResolveBattle { ordres }`, qui **rejoue** la bataille dans la simulation à partir de la graine et des ordres ;
  - le résultat (morts, gaz, lames, Titans abattus) est donc déterministe et rejouable ;
  - « auto-résoudre » garde le modèle de P3.
- **Auto-résolution ↔ combat joué** : le modèle d'engagement de P3 (log-normale + rupture rare) **est** l'auto-résolution. La simulation tactique est calibrée pour que ses pertes moyennes, en combat laissé à l'IA, restent à ±15 % de l'auto-résolution sur un jeu de 6 engagements types. Le calibrage de P3 (AC3-07) reste inchangé.
